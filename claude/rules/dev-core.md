# 开发方法

本文件用于代码行为、接口和多文件实现。Claude 默认加载，不依赖文件扩展名触发；Codex 经 AGENTS.md 的任务入口读取，常驻最低要求直接保留在 AGENTS.md。全局 Core Rules 决定目标与授权，本文件帮助实现已确认的合同。

## 理解当前行为

读取相关实现、调用方、实际输入与项目现状文档；需要判断回归时运行受影响的基线。改变或重新解释既有行为前，以 Git 和 repo-state 确认形成原因及用户裁定。当前代码与文档冲突时保留为未决事实，不把任一方自动当目标。

新建代码、脚本或接口前，先查本仓库已有实现，再查语言标准库、工具原生能力和已装依赖；找到能满足当前合同的就直接复用，确需新写时说明现有能力缺什么。集成陌生库先查与当前任务有关的 API 和实际限制，不只照 quickstart 自写一套替代。陌生 CLI 先读帮助或官方文档；HuggingFace CLI 使用 `hf`。

修改共享接口前查调用方。已授权的接口变更连同必要调用方一起完成；超出目标的破坏性变化先报告。实现中发现设计未枚举的输入组合或边界，先回到行为清单和相关设计，按已有合同判断它应被支持、拒绝还是范围外：结果已确定时自行补行为条目、测试与实现，只有需要新增产品语义时询问；不用逐个追加 case 和分支代替设计判断。

## 实现取舍

需要抽象时看实际复用的语义，不提前增加接口、泛型、参数和扩展点。

准备写 try/except 兜底、fallback、重试、校验、兼容分支、配置开关或状态副本时，先说出它对应的当前真实失败、外部边界或用户要求；说不出就不加，“更安全、更健壮、未来可能用到”不算依据。检查 diff 时按同一依据核对新增机制和外部审查建议。确认属于异常的路径应把失败交到能处理的层，不吞错返回默认值或偷偷换模型、provider、URL、解析器。合同允许的缺省值、部分结果与继续执行保持其领域语义，不因词面像 fallback 就重新分类。

校验放在实际信任边界，内部不重复检查已经成立的条件。修共享函数的根因，不逐调用方叠补丁。派生状态能计算就不另存，新增状态副本须说明现有方法在什么真实场景失效。数据量大时分页或流式处理，不为方便裁掉正文、记录或 top-N 数据。

真实信任边界的一次必要校验，以及使异常明确停止、报告或向上传播的行为要保留；不能把这些与静默吞错、伺候假想调用者的兼容分支一并当成过度防护删掉。数据裁剪须来自用户要求或领域合同，并说明实际保留范围。

用户确认新目标后采用新设计；未要求兼容时删除被替代路径，不留 adapter 或双模式。资料、外部合同或已有无关修改仍按用户授权保护。发现范围外问题给具体影响，不顺带实施。

## 测试与交付

优先复用已有检查，只补足以复现问题、验证修复和保护受影响行为的测试，不因局部修复扩展测试体系。测试期望来自用户目标、接口合同和真实消费者，使用公开行为；修 bug 的回归在修复前确认能因原缺陷失败，再检查修复结果。测试策略、边界与 fixture 选择需要深入判断时用 `tdd`。

迭代运行受影响检查，收尾完成项目规定和本次改动需要的验证。已有结果仍有效时不重复跑全量套件。前端与 UI 的画面和交互必须在实际浏览器中检查，后端 e2e、编译和退出码不能替代；拿不到介质时明确标出未验证部分。代码缺陷先确认检查触达原始失败，再据实际输出验收，不以代码看起来正确宣布修复。完整验收方法见 `~/.claude/rules/verification.md`。

检查 diff 是否包含任务外改动、调试残留、冗余分支和无用中间产物。注释和正式文档描述终态，仅更新本次改动影响的现行说明；修改过程在交回消息说明，不为记录修复经过新增文档。新增机制与外部审查建议按「实现取舍」的依据核对。安全、权限、支付与并发任务按其真实接口及失败条件验收。

commit 使用 Conventional Commits，破坏性改动用 `!`，repo-state 文档确认标记放 footer。

## 工具、进程与并发

搜索优先 `rg` 并限定路径与类型，避免大目录宽匹配。停止服务先确认监听进程或实际启动身份，再终止精确 PID；不用宽匹配 `pkill`、`killall`，`lsof` 查端口时区分监听服务和客户端。

后台工作使用当前运行时支持的进程与等待机制，跨调用持久任务使用对应 runner；不要用 `setsid ... &` 绕过生命周期管理。启动后按实际 PID 确认归属和进程数量。模型、effort 和已选服务合同沿用户配置与 runner 记录传递，不擅自调整。

独立的读取、查询、外部请求和可分离任务并行处理；写同一资源、真实依赖或纯本地计算按实际需要安排。并发度服从工具容量与速率限制，限流时调整并发和退避，不把所有独立请求改为逐个串行。主会话在子任务运行时继续处理独立工作。

## API 与故障处理

按真实接口要求设置认证、超时和重试。认证或权限失败明确报告；可恢复的限流、临时服务故障使用工具已有能力和接口要求，避免重复叠加重试层。LLM 输出预算覆盖本次所需内容，不套用习惯性的短 `max_tokens`；当前任务已明确的参数含义沿该任务约定执行。

失败先区分输入、工具、服务、环境、产物与观察方法。重试须有暂态依据，换方法须能缩小剩余疑问。连续没有实质进展时，先凭已有结果回答两问：现在的思路是正确的吗？沿当前路径继续，还能带来实质提升吗？实质提升看剩余关键问题是否缩小或结果是否更接近目标；答不出有证据的“能”，就换根本不同的思路、角度或拆法继续探索，不在原方案上反复调参、改措辞或加中间步骤。在无法提升的方案上继续开发是愚蠢错误的决定。没有自动复现时仍可读日志、源码和现有证据，未复现的结论注明限度。需要深入定位时使用 `bug-detective`，不按固定失败次数或主观分数强制停工。缺少必要权限、材料或可行路径时给出事实、已排除原因与具体下一步。

## 委派

委派实际可独立完成的问题或产物，给原始目标出处、当前事实、已确认决定、未决项、修改范围与验收方式。只读调查保持中性命题，探索任务给素材与目标，让执行者选择方法；不同路线保持独立，在交回后比较证据。

任务授权准确传递：咨询自带为理解和核验任务所需的本地工作授权（任务相关的记忆与笔记、材料整理、实验、相关文档的完善），已有执行授权不因使用子代理缩减，用户点名保护的对象和明确的只读要求完整遵守。实际等待、进展、取消和 resume 沿对应 delegate 技能；独立审查用干净上下文，按 `~/.claude/references/review-task-template.md` 执行。父会话检查证据与实际产物，不能凭 STATUS 或多数赞成接受结果。
