# 验证与收口

验证回答本次产物能否供实际消费者使用。成本匹配任务，局部编辑和只读回答不触发整套验收流程。Codex 从 AGENTS.md 的任务入口读取本文件。

## 选择有判别力的检查

代码检查真实调用与需要保留的行为；界面检查实际画面和交互；图片、PDF 与文档检查读者实际使用的版本。对文字同时核对事实、论证、条件、现场细节及可读性。

确认实现、调用方、入口、相关文档和用户实际消费的导出版本一致。独立审查用于需要独立判断的问题和用户指定的任务，不机械追加审查轮数。

配置、技能或提示词改动在执行前确定要改善的行为与必须保留的行为，选择真实历史摩擦及弱语境的同构任务，固定输入、材料和判定依据。改动后由干净消费者只凭现行入口与必要原件执行，核对实际取得的规则、来源使用、任务完成、信息保全及用户决定与模型建议的区分。静态 diff、格式、引用、技能调用和文本缩短只能证明各自检查的对象，不能替代内容与行为验收。

声称新版本改善表现或没有回归时，须在相同模型、运行时和任务条件下比较前后产物，说明样本覆盖和不能控制的差异；模型或环境不同的结果分别报告，不据此证明某项配置更优。用户暂停某个模型、额度不足或条件缺失时，不为验收擅自调用或更换模型；完成可做的检查，并把尚未验证的运行时效果明确交还。已有正确任务也要检查，不能只让新失败用例通过。样本随真实疑问选择，不另造固定规模评测体系。

## 非通过先归因

先分清实际产物失败、证据不足、验证器不稳或观察现场不对，再决定修实现、补观察或改检查方法。长会话中 Bash 输出间歇为空或 Read 返回截断，属于观察现场问题：用退出码、`git diff --stat`、计数和校验和这类短输出重建事实，再决定是否重试；Edit 报找不到原文时先用 `git diff` 核对上一次编辑是否落盘，不改锚点硬试。判断依赖人的审美、价值取舍或无法取得的运行条件时，明确交还相应部分。小任务用一句准确说明即可，无需完整状态表。

配置调整后复发的行为，追到最后有证据的正确状态和首次偏离，检查中间的要求删改、加载、委派、纠正和工具操作。规则仍存在只说明没有完全删除，不能据此排除配置影响或直接归因于模型；前后缺少可比较证据时保留因果未定。

验证器也是实现的一部分。修改断言、选择器、截图区域或过滤条件时，说明被检命题为何仍成立；不得为通过而弱化要求、删除有效断言或把真实失败排除在外。用户已授权的修复包括必要的检查修正，改变验收语义仍需用户裁定。

## 交回证据

说明结果、实际执行的检查和剩余缺口。无法自动验证时写清“机械验证到 X，Y 需人工判断”。部分完成与完整交付分别表述，不以没有报错推断任务完成。

子代理交回的 STATUS 表示任务完成度，审查另给产物 VERDICT；EVIDENCE 给出真实文件、运行结果或来源。父会话复核证据及实际产物，发现指控时核对被违反的要求与依据，不能只接受自评或新写的失败断言。格式、事实、行为和视觉检查各自证明自己的结论。
