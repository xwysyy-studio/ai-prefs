# 验证与收敛

> 规则的前置半边管"动手前别乱动"，这份细则管"动手后凭什么说做完了"。
> 标准层文件：只定标准，不写各 skill 的具体验证流程（那些留在对应 skill 里）。
> 下游消费点：`~/.codex/AGENTS.md` §2 After mutating / §6（精简改编 + 指针）。本文件是唯一权威，改动无需逐条同步；仅当原则级内容增删时更新那边。

## 五条原则

1. **消费者边界**：产出渲染 / 生成 / 上传 / 爬取 / 对外消费的交付物时，验被消费的真实产物，不拿生产命令的成功信号充数（退出码 0 ≠ PDF 渲对，HTTP 200 ≠ 字段爬全，CLI 没报错 ≠ 上传成功）。纯只读回答、结果能直接靠文件检查确认的小编辑不触发重型验证；验证成本匹配风险、影响面、交付物类型。
2. **非通过先归因**：拿到失败 / 空 / flaky / 矛盾的结果，先判是哪一种"没通过"再动手。小任务用最小够用标签（失败 / 尚未验证 / 需人工判断）即可，不必每次口头走完六态；复杂现场（截图、爬虫、渲染文档、脆性测试）再用完整六态。
3. **改验证器仍是改动**：归类是只读判断。一旦去改测试 / 选择器 / 裁剪 / 断言，那是普通文件修改，照样受 CLAUDE.md §2 改前确认约束，不是"验证动作"可绕过确认。
4. **禁止给验证器放水**（verifier-shopping）：验证器失败时，改动必须保持或加强被检命题。修错裁剪可以；因为 OCR 老失败就删掉 OCR 检查，不行。
5. **验证不了就交还**：有些目标机器验证不了，显式声明"机械验证到 X，Y 需你判断"，不假装自动化覆盖了。

## 六态（归因词汇）

| 态 | 含义 | 下一步 |
|----|------|--------|
| 已验证 | 验证器稳、看对了东西、证据成立 | 可升级为回归检查 |
| 未验证 | 实现确实没让命题成立 | 改实现 |
| 证据不足 | 没采够证据 | 补观察，别急着改实现 |
| 验证器不稳 | 假阴假阳 / flaky | 先修验证器（受原则 3、4） |
| 现场不对 | 截错区 / 时机早 / 选择器失效 | 换现场，别改实现 |
| 需人工复查 | 机械判不了 | 按原则 5 交还 |

失败阶梯（`rules/dev-core.md`）的"重试 / 换路径 / 停"在最前面接这一步：先归因，再走阶梯。
