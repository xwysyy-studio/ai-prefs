# 验证与收敛

> 管"动手后凭什么说做完了"。Codex 侧消费点在 `~/.codex/AGENTS.md` §3 / §4 / §10；本文件是唯一权威。

## 五条原则
1. **消费者边界**：谁消费产出，就在谁的边界验被消费的真实产物，不拿生产方成功信号充数（退出码 0 ≠ PDF 渲对，HTTP 200 ≠ 字段爬全，CLI 没报错 ≠ 上传成功）。父会话是子 agent 交回物的消费者，按 EVIDENCE 复核不采信 PASS 自评。全局配置的消费者是后续冷启动会话：静态 diff、Core Rules 同步和 router fixtures 只证明接线正确；行为验收至少回放一个真实历史摩擦及一个弱语境同构变体，观察模型是否复原现行合同、区分用户目标与通用原则、保存未决项。上线后仍复发时，用 repo-state friction-audit 追查最后一个正确状态到第一个错误状态，不预设一定是激活失败。纯只读回答与小编辑不触发重型验证；验证成本匹配风险与交付物类型。
2. **非通过先归因**：失败 / 空 / flaky / 矛盾的结果，先判是哪种"没通过"再动手。小任务用最小标签（失败 / 尚未验证 / 需人工判断）即可，复杂现场（截图 / 爬虫 / 渲染文档 / 脆性测试）才走完整六态。
3. **改验证器仍是改动**：改测试 / 选择器 / 裁剪 / 断言照样受铁律 1 改前确认约束，不是"验证动作"可绕过。
4. **禁止给验证器放水**：验证器失败时，改动必须保持或加强被检命题；因为检查老失败就删掉检查，不行。
5. **验证不了就交还**：显式声明"机械验证到 X，Y 需你判断"，不假装自动化覆盖了。

## 六态（归因词汇）

| 态 | 含义 | 下一步 |
|----|------|--------|
| 已验证 | 验证器稳、看对了东西、证据成立 | 可升级为回归检查 |
| 未验证 | 实现确实没让命题成立 | 改实现 |
| 证据不足 | 没采够证据 | 补观察，别急着改实现 |
| 验证器不稳 | 假阴假阳 / flaky | 先修验证器（受原则 3、4） |
| 现场不对 | 截错区 / 时机早 / 选择器失效 | 换现场，别改实现 |
| 需人工复查 | 机械判不了 | 按原则 5 交还 |

失败阶梯（`rules/dev-core.md`）的"重试 / 换路径 / 停"在最前面接这一步：先归因，再走阶梯。
