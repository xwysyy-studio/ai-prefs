# Writing Tone Rules

## 通用 De-AI 写作纪律

> 适用于所有文字产出。目标：消除 AI 生成文字在句法结构和信息组织层面的典型痕迹。

**两个总判据**（优先于下面所有条目，清单没列到的新变种也用它们裁决）：一是删除测试，删掉这句话或这个修饰后读者少知道了什么，答不出就删；二是追问测试，读者追问"这具体指什么"，能用事实或逻辑答上来才留，答不上就换成直白说法或删除。

### 词汇级

- **破折号全面禁止**：`——`、`—` 视为高风险 AI 风格标记。改为逗号、句号、括号或拆句。不用破折号制造补充说明、强调反转或总结收束。
- **正文禁非正式符号**：正文中禁用 `vs`、`~`、`→`，改为"与……相比""约""导致/得到"。LaTeX `~` 作为不间断空格例外。
- **术语纠错全局生效**：用户指出术语不准确后，后续编辑中绝不再使用被纠正的错误术语。
- **代词节制**：少用 `it/they/this/它/该/这一点` 悬空指代，能直接写名称就直接写。
- **比喻节制**：正文默认不加类比。除非确有助于理解，不把概念比作引擎、桥梁、地图、旅程、食谱、生态系统、飞轮、罗盘、镜子、工具箱这类万金油意象（中英文同等适用）。具体例子优先于比喻；原文已依赖的比喻仅在它真正帮助时保留。

### 句式级

- **禁反向句式与假对立**：少用"不是……而是……""并非……而是……""与其说……不如说……"；被否定的 X 必须是读者真实存在、可指认的误解，否则直接说 Y。同一判据管住所有句式变体：不靠声明"我们和别人 / 和过去有什么不一样"立自己，不叙述未被采用的替代方案和妥协过程。例外：Related Work 结尾回扣本文差异（`rules/academic-writing.md`）是合法学术对比。
- **禁预防性澄清与动机声明**：正常读者不会产生的误解不去澄清（"执行 A（不做 B）"，可没人会以为要做 B）；写作动机和立场不显式写进正文（"为避免争议""为保持客观"），这类声明 AI 味重且欲盖弥彰。想写"不做 X""不是 X"之前先问：真有读者会误解成 X 吗？没有就删整句。
- **禁幽灵信息**：正文只描述当前存在的内容。不写"旧版""原来""后来""最终实现中""不再"等历史叙述；已删除或未采用的方案不进正文。Changelog / 迁移文档除外。
- **禁元叙述**：正文只写对象本身，不写写作过程。"本章根据……整理""为了完成报告""按照要求""经过修改""下面我们将介绍"一律删除。
- **禁过度解释**：不解释显而易见的工程取舍、不为自然选择辩护。没有新证据、新约束或新结论的解释段落，删除或压缩为一句事实。
- **禁评价性收束句**：删除"这有效提升了……""该设计保证了……""从而实现了……"等不含新信息的总结句。收束句删掉后段落信息量不减 → 废话，删。
- **禁桥接废话句**：`在此基础上`、`值得注意的是`、`进一步地`、`更重要的是` 后面必须紧跟具体数据、对比或新发现，否则删除。验证：遮住这句话，读者仍能理解下一段 → 删。
- **禁机械平行列举**：重要性差异悬殊的内容不得使用并列格式。核心特性用散文描述，次要特性降级。
- **事件流叙述优先**：方法、流程、系统说明按因果链展开（触发→执行→结果→问题→处理），主语跟着动作走，不先给抽象评价再补事实。
- **中文不要英文直译**：避免名词堆叠、被动串联、长定语前置。中文自然语序：先主体和动作，再条件和结果；必要时拆句。
- **连接词必须有真实逻辑关系**：没有因果不用"因此""所以""从而"；没有递进不用"此外""furthermore"。连贯性来自内容本身的逻辑，不是连接词硬接。
- **句子节奏避免单调**：同一段落内混用长短句，避免连续 3 句以上长度相近、或多句用相同结构开头。本条与「禁机械平行列举」互补（后者管列举内容，本条管句子节奏）。整篇 humanize 的细化节奏规则交 `writing-style` skill。

### 段落级

- **段落单一职责**：一段说一件事。每段首句点明主题，后续围绕同一对象展开。观察/假设/方法/效果混写 → 拆段。
- **段首句具体不空泛**：不要用"为了解决上述问题""基于以上分析""在此背景下"开段，除非后面立即落到具体问题或动作。
- **逻辑靠内容不靠连接词**：`to this end` 前面必须真的有 end。连接词删掉后逻辑断裂，说明段落缺因果——补证据，不是补 therefore。
- **多余内容删除而非修补**：一段内容需要额外解释、限定、圆场才站得住时，先判断它本身该不该存在；不该存在的直接删，连同为它打的补丁一起删。

## User-facing Docs（README / 产品文案 / benchmark 介绍 / 叙述段落）

### 禁用词

**英**：production-ready, seamless, cutting-edge, revolutionize, empower, streamline, unlock, game-changing, next-generation, state-of-the-art

**中**：开箱即用、一站式、赋能、全面、前沿、颠覆、打造、重塑、焕新、新一代

### 叙事

- README 讲**用户视角**的产品故事（做什么 / 为谁做 / 解决什么），不讲 "V1→V2 迁移史 / backward-compatibility"（除非明确写 changelog）
- 默认**散文优先于 bullet**；仅 API 参考 / 配置表 / 步骤清单用 bullet

### Pre-flight tone anchor

新写 README / 产品文案 / 介绍段落前，先输出 2-3 个候选 opening（①极简工具口吻 ②叙事用户故事 ③技术简洁），等用户选定再展开全文。

编辑现有文档的单点修改不触发。
