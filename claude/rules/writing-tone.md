# Writing Tone Rules（de-AI 写作纪律）

> 所有中文 / 学术长文产出自动执行，不等提醒；整篇风格统一 / humanize 调 `writing-style` skill。不适用：commit message、代码注释、对话回复。Codex 侧精简版在 `~/.codex/AGENTS.md` §11；本文件是唯一权威。

**两个总判据**（优先于所有条目，清单没列到的新变种也用它们裁决）：删除测试——删掉这句话 / 这个修饰后读者少知道了什么，答不出就删；追问测试——读者追问"这具体指什么"，能用事实或逻辑答上来才留，答不上就换直白说法或删。

## 词汇级
- 破折号全面禁止（`——` `—`）：改逗号、句号、括号或拆句
- 正文禁非正式符号 `vs` `~` `→`（LaTeX 不间断空格例外）
- 术语纠错全局生效：被用户纠正过的错误术语绝不再用
- 代词节制：能直接写名称就不用 it / they / 该 / 这一点悬空指代
- 比喻节制：默认不加类比；引擎 / 桥梁 / 地图 / 旅程 / 生态系统 / 飞轮类万金油意象不用，具体例子优先

## 句式级
- 禁反向句式与假对立："不是 X 而是 Y"仅当 X 是读者真实可指认的误解，否则直接说 Y；不靠声明"我们和别人 / 和过去不一样"立自己，不叙述未被采用的方案与妥协过程（Related Work 结尾回扣差异是合法学术对比）
- 禁预防性澄清与动机声明：正常读者不会有的误解不澄清；写作动机不进正文（"为避免争议""为保持客观"）
- 禁幽灵信息与元叙述：不写"旧版 / 原来 / 后来 / 不再"等历史叙述（changelog 除外）；不写写作过程（"本章根据……整理""下面我们将介绍"）
- 禁过度解释与评价性收束：不为自然选择辩护；"这有效提升了……""该设计保证了……"删掉后信息量不减 → 删；要靠额外解释才站得住的内容，连补丁一起删
- 禁桥接废话："在此基础上 / 值得注意的是 / 更重要的是"后面必须紧跟具体数据、对比或新发现，否则删
- 禁机械平行列举：重要性悬殊的内容不并列；核心特性散文描述，次要降级
- 事件流叙述优先：按因果链展开（触发 → 执行 → 结果 → 处理），主语跟着动作走，不先抽象评价再补事实
- 中文自然语序：先主体和动作，再条件和结果；避免名词堆叠、被动串联、长定语前置，必要时拆句
- 连接词要有真实逻辑关系：没有因果不用"因此 / 所以"，没有递进不用"此外 / furthermore"
- 句子节奏：长短句混用，避免连续 3 句以上长度相近或同结构开头

## 段落级
- 一段一件事：首句点明主题，观察 / 假设 / 方法 / 效果混写就拆段
- 段首句具体不空泛："为了解决上述问题 / 在此背景下"开段必须立即落到具体问题或动作
- 多余内容删除而非修补：需要额外限定、圆场才站得住的内容，先判断它本身该不该存在

## User-facing Docs（README / 产品文案 / 叙述段落）
- 禁用词——英：production-ready, seamless, cutting-edge, revolutionize, empower, streamline, unlock, game-changing, next-generation, state-of-the-art；中：开箱即用、一站式、赋能、全面、前沿、颠覆、打造、重塑、焕新、新一代
- README 讲用户视角的产品故事（做什么 / 为谁 / 解决什么），不讲版本迁移史；散文优先于 bullet（API 参考 / 配置表 / 步骤清单除外）
- Pre-flight tone anchor：新写 README / 文案 / 介绍段先出 2-3 个候选 opening（极简工具 / 叙事故事 / 技术简洁）等用户选定再展开；编辑现有文档的单点修改不触发
