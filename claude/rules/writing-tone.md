# Writing Tone Rules

所有中文写作、技术说明与交回摘要，以及面向人或其他模型的中文产物，按以下偏好表达。普通对话保持自然语气；论文按其读者和语境行文。完整起草、润色与风格统一使用 `writing-style`，表达模式和样例按具体问题读取。

## 词汇级

- 禁用破折号（`——`、`—`）。正文不用 `vs`、`~`、`→` 代替完整表达，LaTeX 不间断空格与技术语法按原意保留。
- 使用用户既定说法和读者领域的通用术语，保留已确认的术语纠正。内部字段、缩写、项目编号或自造比喻不能代替事实说明；确需新名称时，就近解释含义。
- 用具体对象和动作表达技术含义，避免悬空代词、名词堆叠、文言化包装和拟人。普通口语可自然使用，技术关系应准确完整。
- 表头、分类名与状态标签使用中性、稳定的名称。比喻只在帮助理解时使用，不能成为需要反复猜测的内部术语。

## 句式级

平实写清主语、动作、对象、条件和结果，让每句承接前句的事实或论证。连接词对应真实关系，长短句随内容安排。一段围绕一件事展开，重点得到足够解释。形式按内容之间的关系选择：并列事项和操作步骤用列表，多个对象按相同维度比较用表格，因果推理和叙述用段落，一篇文字可以组合使用。有主线的内容不切成互不相连的短点，需要查阅的内容也不写成逐行阅读的解释。

润色保留事实、论证、例子、现场记录与必要解释。清理元叙述前，先拆出其中有效内容并改成直接陈述，再删无信息的包装。判断具体句子的去留与改法时做对应的检查：删除前问“读者会少知道什么”，确认没有信息损失才删；表述含糊时问“这具体指什么”，用已有事实或逻辑答清，答不清就换直白说法，不补造细节；准备引入质疑、误解、比较或替代定位时，核对它在原文、审稿意见、相关工作或读者实际需要中的出处，没有出处不引入；使用比喻或内部命名时，试着用领域通用术语直接写清对象、动作、条件和结果，更准确就用直接写法。字数更少或句子更短不能证明质量更好。原因未查明就说明未查明，不补未经验证的解释。

对象、范围和贡献正面陈述。需要收窄论断时，直接写证据支持的条件与结论；相关工作比较从对方实际覆盖的范围或证据缺口切入。禁用“不是 X，而是 Y”及其等价句定位自己的工作，也不主动制造误解、争议和替代方案再辩护。真实负面结果和已有文本提出的异议按事实保留。

## 产物与修订

读者没有读过本对话。产物只写其用途需要的事实、解释和结论；写作动机、用户纠正、废弃方案与 agent 工作过程留在交回报告或用户要求的变更记录。

实质删改或内容纠正按 Core Rule 7 执行：先核清需要保留的信息，再重写受影响部分，最后逐段或逐节对照原件检查事实、论证、条件、例子和作者立场。删掉的内容须能说明对读者没有信息损失，或属于用户明确授权的取舍。长篇内容纠正或多轮实质纠正用干净上下文完成定稿，原始材料和完整内容要点一并传入；只指定字句增删时保持无关正文原样。

## User-facing Docs（README / 产品文案 / 叙述段落）

- README 从用户用途讲清做什么、为谁、解决什么。API 参考、配置表和操作步骤使用适合检索与执行的结构。
- 产品文案保持具体中性，禁用 production-ready、seamless、cutting-edge、revolutionize、empower、streamline、unlock、game-changing、next-generation、state-of-the-art，以及开箱即用、一站式、赋能、全面、前沿、颠覆、打造、重塑、焕新、新一代等宣传措辞。
- meta description、og:description、分享摘要与 bio 开头不宣扬论文录用和荣誉，不为 SEO 添加内容。论文名与 venue 放在 Publications、JSON-LD、CV 等职能性位置。
- 已有材料与用户要求足以确定方向时，直接完成授权的起草或修改。仅当未决的受众、内容或风格选择会实质改变成品时询问。
