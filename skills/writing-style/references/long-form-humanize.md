# Long-form writing and revision

Use this reference when a writing task needs work across sections or sessions,
or a final check of the assembled document. The language layer and the user's
requested operation determine what may change.

## Read the whole argument, then choose working units

Read the document and the evidence needed for the authorized task before
editing. Identify how its sections, figures, definitions, and references fit
together. For a local edit, read enough adjacent context to preserve those
relationships without turning it into a full-manuscript rewrite.

Choose working units by meaning and the available context: a section, a group
of related paragraphs, or a complete argument. Keep nearby definitions,
antecedents, citations, and the result being explained available with the
unit. If a unit is too large, split at a meaningful boundary and carry forward
the context needed to interpret the next part.

Do not split inside a citation, number, formula, code block, Markdown link,
or LaTeX environment. Large indivisible elements stay intact. The agent
chooses a safe processing boundary within the authorized task.

## Preserve the intended content

For specified additions or deletions, change the identified content and
preserve unrelated text. For polishing, retain facts, conditions, comparisons,
logical relationships, and the roles of the existing paragraphs. Preserve
established headings and ordering unless changing them is part of the request.
Remove empty repetition while keeping the facts it may contain.

For authorized restructuring, first identify the final content and the role
each part serves. Map the core claims to their source, conditions, supported
scope, and substantive counterevidence. Compare the retained content with each
affected original paragraph or section, then write in the new order. Citations
move with the claims they support. Mathematical statements, code, reference
targets, and figure meanings keep their semantics.

After substantive feedback on facts, meaning, argument, or structure, apply
Core Rule 7 within the requested scope: inventory the facts, reasoning,
conditions, examples, details, and author stance that must remain; check that
inventory against each affected original paragraph or section, then rewrite
the affected content. For substantive correction of long passages or
repeated substantive corrections, use a clean context containing the confirmed requirements, retained content,
and original evidence, without the revision history, to regenerate the
affected portions. Check the generated result against both the inventory and
the originals; a fresh writer's self-assessment does not replace this check.
Check adjacent and analogous passages for the same issue, repair authorized
instances, and report any needed extension. Explicit narrow additions or
deletions preserve unrelated text.

## Work across sessions

Use the project's existing current-state document when the task already has
one. Keep the agreed scope, current input and output, completed sections,
relevant taste decisions, and unresolved substantive issues sufficient for
continuation. Update that state in place; use repo-state to recover the
underlying conversations when needed.

When resuming, compare the recorded state with the actual files and recent
user decisions. Continue the unfinished authorized work. A long document does
not by itself require an additional history of rounds, drafts, and scores.

## Check the assembled artifact

After processing the parts, read the assembled result in order. Check that
transitions express real relationships, definitions still precede their use,
and no part is missing, duplicated, or disconnected. The intended structure
governs this check; restructuring can legitimately change paragraph counts.

Compare retained factual claims, numbers, conditions, and comparisons with
the input evidence. Check that every citation still supports its attached
claim and that reference targets, code, formulas, and non-prose environments
were preserved or changed only within the authorized scope.

Run the relevant structural or reference checks. When the task changes a
rendered document, inspect the actual affected pages for typography, figure
readability, and page breaks. Mechanical checks establish their specific
properties; they do not establish the clarity or faithfulness of the prose.

Perform further revisions when a concrete unresolved problem justifies them.
Repair mistakes and omissions within scope autonomously. Ask the user when
the remaining issue changes a central claim, requires a new direction, or
depends on information only they can provide. Finish when the requested
changes are complete and the actual artifact passes these content checks;
self-assigned style scores do not establish completion.

## Deliver

Put finished prose in the requested output. Keep editing history, work plans,
and commentary out of that prose unless they are part of the requested
artifact. In the handoff, explain the meaningful changes and any remaining
verification limit. Return the requested file, diff, or text without asking
the user to assemble the processed sections.

Use the language layer's expression guidance throughout. For English LaTeX,
follow style-apply.md's Preservation Rules; for Chinese, follow
chinese-writing.md's information and readability criteria.
