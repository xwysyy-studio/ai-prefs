# 术语规范与引用格式

## 一、术语规范

### 首次出现与简称

**基本格式：中文全称(English Full Name, ABB/简称)**

按需使用以下写法：

- 有英文缩写：中文(English Full Name, ABB)
- 无固定缩写但需要英文对照：中文(English Full Name)
- 长术语反复出现：中文（下文简称“X”）

示例：
- 大语言模型(Large Language Model, LLM)
- 交互算法题(interactive problem，下文简称“交互题”)
- 交互评测引擎(interactive evaluation engine，下文简称“评测引擎”)
- 交互器(interactor)
- 查询预算(query budget)
- 通过率指标(pass@k)

### 后续出现

- 已定义缩写/简称：后文只使用缩写/简称（如 LLM、评测引擎、pass@k）。
- 有稳定中文译法且语义明确的：优先用中文（如 求解程序、交互器、校验器）。
- 中文译法不稳定或容易歧义的：保留英文并固定一种写法（如 prompt、token、latency）。

### 术语一致性原则

- 全文同一概念只用一个术语
- 术语“评测/评估/测试”需做语义分工：本文默认用“评测”描述模型能力与题目判定；“测试”仅用于软件工程意义的系统测试（功能/鲁棒性等）
- 如需使用中文简称（如“交互题”“评测引擎”“本文系统”），建议在首次出现处用“下文简称…”明确定义，之后只用简称
- 写作前建立术语对照表（建议放在绪论或系统设计章开头）：

| 中文 | 英文 | 缩写/简称 | 使用场景 |
|------|------|-----------|----------|
| 大语言模型 | Large Language Model | LLM | 全文 |
| 交互算法题 | interactive problem | 交互题 | 全文（若使用简称，首次出现定义后使用） |
| 评测系统 | evaluation system | 本文系统 | 指本文系统整体 |
| 交互评测引擎 | interactive evaluation engine | 评测引擎 | 指本文系统核心模块 |
| 通过率指标 | pass@k | pass@k | 指标 |
| 交互器 | interactor | — | 技术组件 |
| 求解程序 | solver | — | 模型生成并被评测的程序 |
| 查询预算 | query budget | — | 交互限制 |

## 面向交互算法题评测系统：固定术语表（最终版，建议全文默认）

为避免“评测系统/评测引擎/评测器/judge/interactor/solver”等概念混用，建议在绪论或系统设计章开头加入一段“术语约定”，并在全文严格沿用下表（首次出现按“中文(English Full Name, ABB/简称)”给出）。

### 核心术语（按层级约定）

| 层级 | 概念 | 推荐中文（全文固定） | 英文 | 简称/标记 | 说明 |
|------|------|----------------------|------|-----------|------|
| 论文系统 | 系统整体 | 评测系统（或本文系统） | evaluation system | 本文系统 | 指本论文设计与实现的系统整体 |
| 论文系统 | 核心模块 | 交互评测引擎 | interactive evaluation engine | 评测引擎 | 负责运行求解程序、驱动交互器、资源限制与判定 |
| 题目机制 | 题型 | 交互算法题 | interactive problem | 交互题 | 程序与评测器多轮通信、隐藏信息、查询预算 |
| 题目机制 | 评测端整体 | 交互评测器 | (interactive) judge | 评测器 | 题目评测端的统称（环境+交互器+校验器等），避免与“评测系统”混用 |
| 题目机制 | 交互程序 | 交互器 | interactor | — | 与求解程序按协议通过 stdin/stdout 交互 |
| 题目机制 | 校验程序 | 校验器 | checker | — | 对输出进行校验（含非交互题常见 checker/SPJ） |
| 参评对象 | 被测程序 | 求解程序 | solver | — | 模型生成并被评测的程序 |
| 参评对象 | 参考实现 | 标准解 | reference solution | — | 用于生成/验证测试与交互器一致性的参考实现 |
| 协议与约束 | 交互协议 | 交互协议 | protocol | — | 规定 I/O 格式、轮次、查询语义 |
| 协议与约束 | 查询预算 | 查询预算（查询次数上限） | query budget | — | 超限属于协议级失败 |

### 禁止/避免混用（常见错误）

- “评测系统”仅指本文实现的系统整体；题目层面的 “judge” 统一写作“评测器”（首次出现可写作“交互评测器”并注明“下文简称评测器”）。
- “交互评测引擎”是本文系统模块；不要用“judge模块/评测器模块”指代该模块。
- “求解程序”不要与“参评程序/选手程序/solver”在正文中交替使用；若需对照工程命名，可在首次出现处写作“求解程序（solver）”，后文只用“求解程序”。
- “标准解”与“参考解/标程”选一种并固定，本文默认统一用“标准解”。

### 术语约定段落模板（可直接粘到论文中）

> 为便于表述，本文对若干术语作如下约定：将本文实现的整体系统称为“评测系统（下文简称本文系统）”，其核心执行模块称为“交互评测引擎（下文简称评测引擎）”；对交互算法题而言，评测端整体称为“交互评测器（下文简称评测器）”，其中与求解程序进行多轮通信的程序称为“交互器”。除非另有说明，本文中的“评测”均指基于上述约定的自动化评测过程。

### 失败类型（建议统一缩写）

| 缩写 | 中文建议 | 英文 | 说明 |
|------|----------|------|------|
| OK | 通过 | Accepted | — |
| WA | 答案错误 | Wrong Answer | 逻辑/算法错误 |
| PE | 输出格式错误 | Presentation Error | 非法输出/格式不符合 |
| QLE | 查询超限 | Query Limit Exceeded | 超过查询预算 |
| IDLE | I/O 死锁（空闲超时） | Idle / Deadlock | 程序阻塞、等待输入等 |
| CE | 编译错误 | Compile Error | — |
| RE | 运行时错误 | Runtime Error | 崩溃/异常退出等 |
| TLE | 超时 | Time Limit Exceeded | — |
| MLE | 超内存 | Memory Limit Exceeded | — |

## 二、引用格式（GB/T 7714 变体）

### 正文引用格式

使用 **[数字]** 格式（上标或行内均可，中文学位论文通常用行内）。

**标点位置建议：** 引用标记通常置于句末标点之前，如“……[12]。”；并列引用按同一规则处理。

两种句式：

- **叙述式**（作者是主语）：
  > 杨泽洲等[13]系统综述了基于深度学习的代码生成方法。
  > Chen等[1]提出了HumanEval基准。

- **注释式**（引用是补充）：
  > 现有基准对交互题的覆盖极为不足[4,5,12]。

### 多篇引用

- 连续编号：[1-5]
- 不连续：[1,3,7]
- 混合：[1-3,7,12]
- 按主题分组引用，避免"[1-30]"式堆砌

### 参考文献列表格式

最终条目格式以学院模板（附件1.2）为准；下列为常用的 GB/T 7714 变体模板。

**题名大小写**：英文文献题名按来源保留 sentence case，不统一改 Title Case；专名、缩写、模型 / 会议 / 项目名称按原文保留（如 `InterCode`、`NeurIPS`、`GPT-4`）。

#### 期刊论文

```
[编号] 作者1, 作者2, 作者3等. 题名[J]. 刊名, 年, 卷(期): 起止页码.
```

示例：
```
[13] 杨泽洲, 陈思榕, 高翠芸等. 基于深度学习的代码生成方法研究进展[J]. 软件学报, 2024, 35(2): 604-628.
```

#### 会议论文

```
[编号] 作者. 题名[C]//会议名. 地点: 出版者, 年: 起止页码.
```

示例：
```
[8] Yang J, Prabhakar A, Narasimhan K, et al. InterCode: Standardizing and benchmarking interactive coding with execution feedback[C]//Advances in Neural Information Processing Systems. 2023: 23826-23854.
```

#### 学位论文

```
[编号] 作者. 题名[D]. 城市: 学校, 年.
```

#### 预印本（arXiv）

```
[编号] 作者. 题名[EB/OL]. arXiv preprint arXiv:XXXX.XXXXX, 年.
```

示例：
```
[1] Chen M, Tworek J, Jun H, et al. Evaluating large language models trained on code[EB/OL]. arXiv preprint arXiv:2107.03374, 2021.
```

#### 在线资源

```
[编号] 作者. 题名[EB/OL]. URL, 访问日期.
```

### 作者姓名格式

- 中文作者：全名，姓在前名在后
- 英文作者：姓+名首字母（Chen M）
- 三人以上：前三人+等/et al.

### 格式特殊要求（按目标学校）

- **近3年文献须超过30%**
- 参考文献标题："参考文献"，黑体小2号加粗居中
- 正文：宋体小4号

## 三、高风险引用行为

| 行为 | 风险 | 改正 |
|------|------|------|
| 引用堆砌 [1-30] | 显得敷衍 | 分类引用，每类2-6篇 |
| 只引不评 | 未展示理解 | 加比较句 |
| 遗漏最接近工作 | 审稿人会指出 | 务必引用并直接对比 |
| 引用过时版本 | 如arXiv已发表 | 更新为正式发表版本 |
| 自引过多 | 有自我宣传嫌疑 | 控制比例 |

## 自查清单

- [ ] 所有术语首次出现时给出英文全称
- [ ] 全文术语一致，无近义词交替
- [ ] 引用格式统一（叙述式/注释式搭配使用）
- [ ] 无引用堆砌
- [ ] 最接近工作被引用并比较
- [ ] 参考文献格式符合 GB/T 7714
- [ ] 近3年文献比例≥30%
