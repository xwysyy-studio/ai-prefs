# 中文表达问题与修改示例

本参考帮助审读报告、技术笔记、综述和一般中文。模式用于定位问题，不能证明文本的作者身份，也不构成逐项消除词语的任务。先按 chinese-writing.md 确定用途和修改范围，再看当前句段如何影响理解。明确的用户表达偏好继续生效。

改写前确认原句提供的事实、判断、条件、例子和关系。删掉后读者会少知道有效内容，就保留或重写这部分；模糊处用已有事实写清，没有依据时不补细节。引用、专有名词和被讨论的原句按任务保护。下面的练习只说明表达选择，不提供现实事件或产品的事实依据。

## 主体与动作被抽象表述盖住

“能力的集成”“提供了入口”“实现了提升”等表述有时让读者先猜谁在做什么。回到原文已给的对象和动作，把它们放进句子主干。身份定义和准确的抽象概念可以保留，不按名词数量判错。

> 原文：规则和工具也提供了定制插件的入口。
>
> 用户改法：规则和工具也可以根据需求自定义。

这处实际改稿直接说出可以做的事。上下文没有说明定制方式时，不能补成某个具体按钮、配置文件或操作步骤。[用户改稿来源](https://github.com/xwysyy/AI-Plugin-Survey/commit/d0afcf22f40a2c3b1be42ab902b54f0041cdcb33)

长定语和嵌套从句的问题也在于读者迟迟找不到主体。拆开时保留约束的归属：

> 原文：这是一个能在不上传源代码的情况下对本地文件执行规则检查的工具。
>
> 改写：这个工具在本地文件上执行规则检查，无需上传源代码。

“对首次登录的用户，系统要求完成验证”中的适用对象不可丢。“当……时”可能明确时点或条件，不能仅按句形删去。“是”“有”与被动句表达准确时保留。

以下句子出自一份被用户否决的方案汇报初稿：

> 关联两侧数据，可以在同一开发会话中查看模型用量、CodeGraph 调用及内部检索开销，为定位优化环节提供依据。
>
> 这一选择主要考虑对检索前后行为的覆盖，以及在线采集和历史导入的复用。

第一句没有说明由谁关联、由谁查看，“为……提供依据”也没有说明依据什么判断，这个句式在同一篇初稿的开头和结尾各出现一次。第二句用“这一选择”作主语，把“要看到检索前后的行为”压成了“覆盖”。修改时从材料里找出执行关联的对象和使用结果的人，把他们写进主干，再写清想看到什么；材料没有交代时不能自行指定。只在确实说明用途的地方保留一次用途短语。

## 评价盖住事实，或改写增添了事实

“显著提升”“具有重要意义”“为未来奠定基础”等词需要结合上下文判断。原文已有结果、对象或用途时直接写清；没有时不发明数字、具体机制和因果。媒体报道、引用次数、用户规模等真实信息按用途保留，不用它们替代对工作本身的说明。

> 原文：新流程大幅缩短了处理时间。处理一次任务从两小时降到四十分钟。
>
> 改写：新流程把一次任务的处理时间从两小时缩短到四十分钟。

这项改写使用已有数值。若原文只有“处理更快”，可以保留该说法并指出缺少比较细节，不能写出类似数字。虚假新颖性、任意的大范围外推和营销措辞也按其实际内容处理。

“开销不会凭空消失，只是从 token dropping 转嫁到了显存、通信和调度上”应当保留：它说明系统代价去了哪里，承担技术笔记的结论。相反，单独说“未来一片光明，迈出了重要一步”，又没有具体判断依据或计划时，可以去掉空泛包装。

## 解释与限定的作用

“这说明”“因此”“代价是”后面可能提供推理、条件或代价。读它与前句的关系，确认是否增加了读者需要的信息；因果还未成立时不能靠换词补出因果。作者的推测、观点和归属也属于原意。

> 原文：根据现有记录，这个问题可能与缓存有关，但还没有复现。
>
> 保留：记录依据、可能性和未复现状态分别限定了判断，不能压成“缓存导致了问题”。

“可以潜在地可能影响结果”可改成“可能影响结果”，保留不确定性即可。多重限定各有不同作用时则要保留。“专家认为”之类归因不够具体，要查给定来源能否补清；找不到身份就保留来源缺口，不能虚构机构或把判断写成事实。

“截至某日期”可以限定信息有效时间；读者需要确切年份而材料只给出年代时，“现有资料未给出确切年份”直接回答了这个问题。删除模型自述的知识截止免责声明时，保留其中对读者有用的日期与不确定性。

一条缺失信息是否值得写入，取决于当前问题。以下笔记只解释计算与系统代价，前文没有对训练稳定性作出判断：

> 原文：Dropless 方案保留所有路由分配，并按实际 token 数组织专家计算。开销不会凭空消失，只是从 token dropping 转嫁到了显存、通信和调度上。上述讨论涉及计算与系统代价，未给出训练稳定性的比较结果。
>
> 改写：Dropless 方案保留所有路由分配，并按实际 token 数组织专家计算。开销不会凭空消失，只是从 token dropping 转嫁到了显存、通信和调度上。

末句没有限定前面的机制或代价，也没有回答读者的当前问题，可以去掉。仅把它改得更短或更客观，仍保留了多余说明。若读者问“两种方案哪一种训练更稳定”，同一缺口就应直接说明：“现有材料没有提供训练稳定性的比较，无法据此判断。”原稿若已经无据推断训练更稳定，应在获准修改内容时纠正该推断，而非给强结论再加一句缺证说明。

句子是否以“本文”或“我们”开头不决定去留；它可能在交代研究对象、作者解释或读者需要的范围。技术笔记中的“具体取决于是否允许重路由”同样应保留，它说明其他专家有空位却未必能接收 token 的条件。

## 衔接没有交代对象或关系

新段落以“看起来”“问题在于”“更重要的是”开头时，先判断读者能否确定它谈的是哪个对象。前文只有一个明确对象时，代词可以承接；前文比较多个对象时，直接点明名称。已有指代就不再机械补一个“这”。

假设前文分别介绍了代码索引与工具检索：

> 原文：这能减少进入上下文的内容。
>
> 处理：回到材料确认本句谈的是哪种机制，再用该机制作主语。未确认时不能猜。

段落间的关系可以是比较、展开、例证、先后、转折或推导。用已经建立的信息承接新内容，连接词只说明确实存在的关系。“此外”“然而”并非需要清除的词；更换同义连接词也不能修好没有关系的两段文字。

## 形式与内容关系不符

清单、操作步骤和可比较字段适合并列，完整项目应保留。叙述里反复用相同骨架罗列材料，导致读者看不出差异和关系时，再合并共享内容或改变其中一句的展开方式。三项并列、长短句相近或多个案例本身都不构成问题。

反方向的问题同样常见：运行命令、文件用途、期望结果或多个对象的同维度比较写成大段解释，读者只能逐行寻找需要的信息。这类内容改用清单、命令和表格；用途、各部分的关系和容易误解之处仍用完整句子说明。去 AI 味针对装饰和解释腔，不针对列表和表格本身。

> 原文：系统负责采集、存储、展示。
>
> 保留：三项动作都明确，不需要为了减少顿号改成“从采集到展示”，后者不再明确存储环节。

冒号用于引语、定义、总分说明或引出操作项时可以清楚地表达层级。前面的提示语没有信息也不承担衔接时，直接说内容：

> 原文：核心是：先处理付款失败的订单。
>
> 改写：先处理付款失败的订单。

“本次只检查两类失败：超时和解析错误”限定了范围，应保留。仅宣布“下面有几个方面”的句子可删去或与上文衔接，但正文里的清单及其适用条件不能一起消失。授权的内容重组可以改变材料主次；轻量润色不据列表形式自行删减观点。

“随后新版本上线了。没有公告。没有迁移文档。旧接口直接失效了。”可以写成“新版本上线时没有发布公告和迁移文档，旧接口直接失效”，保留事件与条件，同时避免不必要的戏剧性断句。引语、叙事节奏或有意强调已经服务当前表达时，按原语体处理。

## 自造名称、比喻和对比让读者多猜一步

同一概念使用同一术语。“助手”“执行器”“智能中枢”若在说同一对象，应按领域通用称呼或用户既定名称统一。真实的概念区别需要解释，不为了词面变化把它们混用。

比喻应帮助理解具体关系。工具被描写为智慧导师、永不疲倦的管家，或者概念被反复包装成飞轮、底座、旅程，而机制仍不清楚时，回到它实际做了什么。不能从一个空泛比喻推导出原文未给出的功能；真实文学表达和作者观点按原体裁保留。

“对称是信任的语言”这类格言式句子，需要回到原文找出所指的对象和关系。材料不足就指出含糊处，不能替作者创造心理效应或失败原因。

介绍对象、范围和贡献时直接陈述，使用读者可见的实际比较依据。不要先虚构一个误解再推翻。真正消解歧义的说明要保留其有效内容，例如：

> Token dropping 通常不是把整个 token 从模型里删掉，而是这个 token 在当前层没拿到原定的专家计算。

这句在消解两个具体含义之间的歧义；按任务改句形时也必须保留这一区别。真实负面结果、作者分歧和已有异议同样不能因为带有否定而删除。

## 交流包装与正文用途混在一起

“希望这对您有帮助”“你之前要求的版本”“这一节我们将详细介绍”等文字，通常属于对话或写作过程。正式正文直接完成介绍与解释，修订历史放在交回说明。清理前拆出其中有效的信息，不把实质内容一起删除。

“说实话”“坦白说”等自然出现在用户口语或个人稿件里，可以体现其语气；每段固定摆出坦率姿态却没有新增意思时，再去掉包装。不要为显得自然补上第一人称经历、情绪、闲话或错字。

通用的“挑战与展望”如果只是赞扬和重复，可以删去空话；原文给出的失败、限制、具体计划及其条件继续保留。标题和结尾是否需要，取决于文章用途及已授权结构。

## 强调与标点分散注意力

按用户的格式选择使用标题、列表、引号和加粗。界面原话、被讨论的术语需要明确引用；普通词语不必层层加引号。关键词或结论可以强调，连续整句加粗或逐句贴标签却没有帮助检索时，去掉这些装饰，再按内容关系重排：有推理关系的写成连贯段落，并列事项、操作步骤、比较和术语定义用适合查阅的清单或表格。

用户全局禁用破折号，正文改成合适的逗号、句号或括号，保留原来的补充、转折与范围。技术语法和任务要求保留的原文引用按其用途处理。
