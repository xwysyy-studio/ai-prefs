# 绪论写法（中文学术）

绪论是审稿人/答辩老师对论文的第一印象，决定了对全文的期待水平。

## 推荐结构（8段式，中文学位论文/期刊）

### 第1段 — 研究背景与动机

- 点明研究领域及其重要性
- 具体化，避免泛泛而谈（不要"随着人工智能的发展……"开头）
- 1-2个关键引用支撑重要性声明

**示例开头：**
> 大语言模型(Large Language Model, LLM)在代码生成领域展现出强大的能力，已成为软件工程与人工智能交叉领域的研究热点。竞赛编程作为衡量代码生成能力的重要场景，催生了 HumanEval[1]、APPS[3]、LiveCodeBench[4] 等一系列评测基准。

### 第2段 — 国内外研究现状

- 按主题（非按时间）组织最相关的工作
- 引用代表性工作（2-6篇），不堆砌
- 用比较句式："X等[n]关注……，Y等[m]则……"

### 第3段 — 现有不足（Gap）

- **一句话**点明核心不足，用"然而"/"但"明确转折
- 紧跟说明为什么这个不足是重要的（后果）
- 引用最接近的工作，指出其具体做不到什么

**Gap 句式模板：**
> 然而，上述基准几乎完全聚焦于批处理式问题，而对需要程序与评测器进行多轮交互的交互算法题覆盖极为不足。

**措辞注意：**
- 避免贬低前人："X存在严重缺陷" → "X主要关注……而未涉及……"
- 用中性措辞："现有工作尚未涉及" / "在这一方面仍处于空白"

### 第4段 — 核心思路（高层概括）

- 用通俗语言描述本文的核心方案
- 如有系统架构图，指向图1
- 不要在这里展开细节

**模板：**
> 针对上述问题，本文设计并实现了一套面向交互算法题的大语言模型评测系统。如图1-1所示，该系统包含……

### 第5段 — 挑战/难点（可选但推荐）

用编号列表列出关键技术挑战：

> 实现上述目标面临以下挑战：
>
> (1) **交互器构建**。如何自动生成……
> (2) **双进程通信**。如何实现……
> (3) **失败诊断**。如何区分……

### 第6段 — 贡献（明确列出）

格式固定，便于审阅：

> 本文的主要贡献有以下N点：
>
> (1) 提出/设计了……（是什么 + 有什么特点）
> (2) 实现了……（技术要点 + 效果）
> (3) 开展了……（实验规模 + 关键发现）

**注意：**
- 每个贡献用一句话概括，避免过长
- 贡献数量2-4个为宜
- 每个贡献后续在实验中必须有对应验证

### 第7段 — 结果预告（可选但强烈推荐）

- 1-2句最强的定量结果
- 连接回 gap，说明本文填补了什么

### 第8段 — 论文结构（章节路线图）

> 本文其余部分的组织如下：第2章介绍……；第3章描述……；第4章阐述……；第5章开展……；第6章总结全文并展望未来工作。

## 起承转合微技巧

- 每段结尾用前向指针："这一需求促使……" / "为解决该问题……"
- 用"然而/因此/与之相对/由此可见"使转折显式化
- 每节开头先给结论，再展开细节

## 高风险措辞

| 高风险 | 替换 |
|--------|------|
| "本文首次……" | "据现有文献所知，目前尚无工作……" |
| "创新性地提出" | 直接说"提出了……"并说明新在哪 |
| "显著提升" | 需附具体数字 |
| "填补空白" | "为该领域提供了……" |

## 自查清单

- [ ] 第1段具体、不泛泛
- [ ] 最相关工作被引用并直接比较
- [ ] Gap 句显眼，用"然而"/"但"转折
- [ ] 贡献明确列出，与实验章对应
- [ ] 无过度声称（"首次"/"革命性"）
- [ ] 论文结构路线图存在
- [ ] 绪论结尾自然过渡到第2章

## Top-Venue English Paper（思路，非固定段落数）

上方 8 段式面向中文学位论文/期刊。投 top venue 的英文技术论文，Introduction 的核心是六个功能位的逻辑链：

1. **Background + Running Example**：场景重要性 + 一个贯穿全文的具体例子
2. **Existing Limitations**（≤3）：现有工作具体做不到什么
3. **Problem / Goal**：本文要解决什么（一句话）
4. **Key Challenges**（≤3）：为什么不能直接做，难在哪
5. **Solution Overview**：我们怎么做的（一段高层概括）
6. **Contributions**：本文贡献列表

**核心纪律**：limitation→challenge→method module→contribution 每个箭头都要能追溯。任何一个断了就是结构问题。功能位不等于物理段落数——可以合并，但逻辑链不能断。

**Technique vs Benchmark paper 区别**：technique paper 的叙事轴是 Key Idea/Mechanism；benchmark paper 的叙事轴是 Evaluation Gap + Benchmark Design Rationale，problem definition 本身就是贡献，实验目的是"揭示能力边界"不是"证明我最好"。Benchmark intro 的功能位替换为：Background + Running Example → Existing-Benchmark Limitations → Research Questions → Design Considerations → Our Proposal → Contributions。

**Running example**：intro 里引入的例子必须在 Method（作为 walkthrough）和 Experiments（作为 case study）中兑现，不能用完就丢。
