# Introduction 写法

Introduction 要让领域读者理解本文处理什么问题、为什么值得处理，以及本文怎样回应。背景的篇幅按读者已有知识安排，重点放在当前工作真正需要解释的概念和区别。

## 从研究问题安排内容

依据材料选择和组织下面的内容。它们可以合并、调整顺序或在已经清楚时省去重复说明，不对应固定段落数。

| 内容 | 需要讲清的关系 |
| --- | --- |
| 背景与具体问题 | 场景中的哪项能力、现象或困难与本文有关。 |
| 相关工作与覆盖 | 已有工作提供了什么，本文要讨论的具体问题还缺什么。 |
| 研究目标与挑战 | 本文要回答什么，现成做法为什么不足以回答。 |
| 核心思路与方案 | 这项思路如何回应问题，必要设计为何与之相关。 |
| 贡献与发现 | 本文实际提供了什么，以及材料支持哪些结果或认识。 |

问题、思路、设计和贡献应能互相说明。Technique paper 通常需要解释关键机制；benchmark paper 通常需要建立测量对象、评测缺口与设计依据，并说明它揭示的能力表现。不能为了填齐结构给已有结果强加新机制或额外贡献。

具体例子在帮助读者理解新任务、难点或方法时使用。需要贯穿后续推导的例子保持对象与条件一致，在相关章节继续解释；只承担动机说明的例子可以在完成作用后结束。例子不是每篇引言的必选项，也不能让假设场景变成实际实验。

## 根据与已有工作的关系展开

- 已有方法逐步解决相关困难时，说明这些进展与目标场景仍未解决的问题，最后准确落到本文的切入点。
- 经典工作已经包含与本文相近的思路时，先交代这项思想来源，再说明其在当前任务中的覆盖和本文的推进。
- 缺少直接可比的工作时，先定义当前问题及其必要概念，再解释与相关方向的联系，不制造一个并不存在的共同缺陷。

按问题综合材料，让引用附着于实际贡献和判断。篇幅集中在最相关的差异，避免逐家罗列或为每项工作编一个缺点。增量改进也应说明它回应的真实技术问题，使读者理解为什么需要这一步。

## 用材料支持定位与语气

从相关工作实际覆盖的对象、条件和证据切入，说明差异及其后果；不先编造读者的误解再为本文辩护。研究问题、贡献和成立范围正面写清，真实负面结果与读者可见的异议按事实保留。

优先权和新颖性表述需要来源支持，窄限定本身不能证明“首次”。结果与方法的含义按实际材料表达，不用宣传词替代解释。读者需要知道的限制就近说明，不把内部修订讨论写进引言。

读完引言时核对：读者能否说清研究问题、已有工作的相关位置、本文思路和主要贡献；每个保留的挑战是否得到回应，贡献是否对应实际材料或尚待取得的结果。检查所用例子与后文是否一致，完成其作用的背景和动机不必逐章重复。
