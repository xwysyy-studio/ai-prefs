# 中文写作（统一规范层）

中文写作的唯一入口层，覆盖技术笔记、博客、README、项目文档、知识库条目。润色、去 AI 味、改写走同一套规范，不按任务关键词分岔。学术论文写作在英文层（`style-apply.md`），中文层不做学术写作。

## 总判据（先于一切模式清单）

润色不等于缩字数，去 AI 味不等于删信息。这一层只有一个目标：让文字像懂行的人用母语写出来的，信息一点不少。

- 逻辑通顺优先：先修表述不通、衔接断裂、主谓搭配错位的句子，从中文母语者视角检查信息展开顺序。这类问题比任何 AI 用词都优先处理。
- 通顺的句子不动：没有命中具体问题的句子保持原样，不为"更简洁"重写。
- 信息守恒：改写前后逐段自问"删掉的内容读者是否少知道了什么"。答得出具体损失就不能删；答不出的才是真套话。
- 长度不是质量信号：一次合格的去 AI 味，字数可以不变甚至变多。若总字数下降超过一成，逐项说明删掉的是什么、为什么是零信息。
- 换具体优于删除：模糊表述的正确修法是换成上下文里已有的具体事实；上下文没有可换的事实时，保留原信息只调表述。禁止用删除冒充修复，也禁止发明新事实。

## 工作流

1. 通读全文，理解每段在讲什么、结论靠什么支撑。
2. 第一遍只标问题不改：逻辑不通处、AI 模式簇（目录与判定边界见 `patterns-chinese.md` 头部）、英文句法直译处。
3. 逐段改写命中的句子，未命中的照抄。技术内容、因果解释、数据一律保留。
4. 按总判据自查，输出修改说明（改了哪些类型的问题、字数变化）。

单段粘贴的轻量场景按最小化编辑处理：保留作者措辞，只修通顺问题，不重组结构。用户说"只标不改 / detect / audit"时进入只审计模式：输出问题位置、类型和原文引用，不改写。

## 母语读感的落地手法

词汇 / 句式 / 段落三级规则的唯一权威是 `~/.claude/rules/writing-tone.md`（Codex 侧精简版在 `~/.codex/AGENTS.md` §4），本节只补可直接套用的手法：

- 长短句交替：长句（30 字以上）之后接短句。连续三句同长度或同结构开头时，改写其中至少一句，换主语或状语前置。
- 数据句与解释句交替：先给数字，再给解读；不连续堆数据句，也不连续堆定性句。
- 事件流叙述：按"触发、执行、结果、处理"的因果链展开，主语跟着动作走，不先抽象评价再补事实。

## 术语

- 英文术语首次出现给出中文含义或英文全称，如"大语言模型(Large Language Model, LLM)"；此后统一用缩写。
- 中文译法不稳定的术语保留英文并全文固定一种写法（如 prompt、token）。
- 同一概念全文只用一个词，不交替使用近义词。

## 体裁差异

- 技术笔记：解释性句子承担因果推理，是信息不是填充；"开销从 A 转嫁到 B"这类收束句是笔记的结论，删了等于删信息。
- 博客与随笔：允许观点、第一人称和节奏变化；有真实态度的句子不算 AI 味。
- README 与产品文案：按 `~/.claude/rules/writing-tone.md` 的 User-facing Docs 区执行。
