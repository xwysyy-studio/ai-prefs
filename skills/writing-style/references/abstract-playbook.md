# 摘要写法（中文学术）

目标：用一段话让读者快速了解论文的核心内容，决定是否继续阅读。

## 中文摘要模板（6-8句）

| 序号 | 角色 | 内容 |
|------|------|------|
| 1 | 背景 | 领域重要性 + 问题定位 |
| 2 | 现状 | 现有工作做了什么 |
| 3 | 不足 | 现有工作缺什么（一句话点明 gap） |
| 4 | 方案 | 本文做了什么（高层概括） |
| 5 | 方法要点 | 关键技术/设计（1-2个亮点） |
| 6 | 结果 | 具体实验结果（带数字） |
| 7 | 意义 | 结果说明了什么（有界结论） |

### 模板示例

> [背景] 大语言模型在代码生成领域展现出强大的能力，竞赛编程评测基准是衡量其能力的重要手段。[现状] 现有基准如 HumanEval、LiveCodeBench 等已对批处理式编程任务进行了广泛评测。[不足] 然而，这些基准对需要程序与评测器进行多轮交互的交互算法题覆盖极为不足。[方案] 本文设计并实现了一套面向交互算法题的大语言模型评测系统，[方法要点] 包含自动化数据构建流水线、双进程交互评测引擎和多维度诊断分析模块。[结果] 基于 322 道交互算法题对 N 个主流大语言模型的评测实验表明，……。[意义] 实验结果初步揭示了当前大语言模型在交互场景下的能力边界。

## 英文摘要

- 内容与中文摘要对应，不是逐字翻译而是同义改写
- 用主动语态："This paper presents…" / "We design and implement…"
- 英文摘要中可使用 "we"（国际惯例）

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 背景过多，贡献过少 | 背景限制在1-2句，贡献+结果占主体 |
| 只说做了什么，不说结果 | 必须包含至少一个具体数字或定量结论 |
| 罗列所有工作而非聚焦 | 只写1-2个核心贡献 |
| "gap"不明显 | 用"然而"/"但"明确转折 |
| 论断过强 | 用"初步表明" / "在一定程度上" |

## 关键词选取

- 3-5个，覆盖：研究领域 + 核心方法 + 关键技术
- 示例：大语言模型；交互算法题；代码生成评测；竞赛编程；自动化评测
- 避免过于宽泛（如"人工智能"）或过于狭窄
- 中英文关键词一一对应

## 引用规范

- 摘要中**不引用文献**（中文学位论文惯例）
- 所有具体声明（基准名称、方法名等）在正文中引用

## 自查清单

- [ ] 包含问题+方法+结果三要素
- [ ] 有至少一个具体数字或定量描述
- [ ] "不足/gap" 句明确存在
- [ ] 论断有界，无过度声称
- [ ] 关键词3-5个，中英文对应
- [ ] 中文摘要无引用标记
- [ ] 字数适中（中文300-500字为宜）

## English Abstract（top-venue 思路）

上方面向中文学位论文/期刊摘要。英文 top-venue 摘要的思路是五个功能句（不是五句话，是五个功能）：

1. **Problem + Background**：什么任务、为什么重要
2. **Why Needed**：现有工作缺什么（gap 一句话）
3. **Challenges**：为什么难（可选，有则更强）
4. **How**：我们怎么做的（核心方法一句话）
5. **Results**：具体数字 + 有界结论

默认不引用文献。必须有至少一个具体数字。benchmark paper 的 results 侧重"揭示了什么发现"而非"超过了 baseline 多少"。
