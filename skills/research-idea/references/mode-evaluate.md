# Mode: Evaluate（story 体检）

只在故事已经成形（挖出了 story 位置、能一句话讲清）后启用。任务是替用户做最后一次清晰度与成色体检。三个 mode 里只有这里可以否定一个故事，**不可跳过**。

## 姿态

对抗性但克制。主动找会让故事立不住的地方，同时记住，简单本身从来不是毛病。所有问题都围绕外行能否看懂、切入点是否有意思、论文各部分能否自然服务同一个故事。

## 几个朴素的问题

不拿禁令表逐条打钩，就问这几句：

- 一个外行审稿人扫一眼，懂不懂这个故事在说什么、为什么值得做？讲不清就先回去把话讲清，不是急着否。
- 外行看懂之后是什么反应？"这个切入点我没想到过"能立住，"这我上我也行"就是 borderline 到 reject 之间。判的是看见这个缺口可不可预料，不是执行难不难：简单照样合法，但要的是事后看简单（看懂了拍大腿），不是谁坐下来第一步都会做的显然；看标题就能猜到结论，独特性通常还没长出来。
- 指标或方法像不像从故事里自然长出来的？读者该先看懂你在乎的那个对象，再明白这个指标 / 这个方法只是把它落实下来的一步。一上来就是性质清单、权重理由、消融，或者一堆模块和损失项，通常说明故事还停在设计备忘录，回去先把对象讲清楚。复杂度要是在悄悄爬（堆参数、要一堆消融、把一个体面概念整套理论实现一遍），多半那个简单的 idea 还没找到。
- 水面下有没有一个小而真的观察撑着？还是只是"换了个说法"？观察还没着落时，最有用的动作是去看已有工作的实际表现，确认这个 gap 确实存在。
- 删掉自定义内容后，剩下的是不是任何从业者都会写出的教科书流程？如果是，故事还缺一个能代表作者判断的切入点。
- 能否指出一个现有讲法难以解释、而这个新切入点能够讲通的具体场景？具体场景说不出来，framing 仍然只是换名。
- 这个维度的粒度，审稿人有没有分辨率？太细太内部没人关心，太粗成了空话。
- 这个故事自然需要读者看到哪些对比、消融、案例或分析？先说清每组结果在论文里回答什么，实际实验由用户决定并推进。

**干净地补一个圈子在乎的缺失维度，是合格的故事，不因为简单、或"别人没测过"，就判它增量。** 真的空了才说不，简单不是说不的理由。

命中真问题就直说，给最小修法，或打回 divergent 换角度。默认结论只依据故事成色与用户所在领域的分辨率；专项方法审计由后续明确请求触发。

## 起名字：让旁观者从故事里抽

故事立住后给标题、framing、方法或指标起名字。把核心例子、一句话 story、失败现象和已有摘要交给一个干净上下文，让旁观者圈出最能代表这个故事的名词与动作，再重组两三个候选。选择外行看到后能立即想起核心例子的名字；需要额外解释的候选继续简化。名字可以带一点值得探究的惊喜感，并沿用故事中已经成立的概念。

## 结论

三档 + 最优先 2-3 个行动：故事立得住 → 去写（转 `writing-style` 英文层起草）；要调 → 回 divergent 或 seed-brief；真不成立 → 换方向。Novelty 没实际检索过 → 标 `unverified; literature check required`，不凭记忆下结论。真去查时先自问"别的社区会把这个机制叫什么"，拿别名再查一轮：同一机制在别的圈子常换个名字，这个盲区是词汇性的，只靠自己的词汇加长时间窗补不回来。对到 closest prior 时把已发表当地板：已发表约等于过时，做到同等水平只能降档投，故事的位置要在地板之上。最终决策权在用户。
