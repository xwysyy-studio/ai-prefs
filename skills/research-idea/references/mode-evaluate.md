# Mode: Evaluate（story 体检）

只在故事已经成形（挖出了 story 位置、能一句话讲清）后启用。任务不是补工程洞，是替用户做最后一次清晰度与成色的体检。三个 mode 里只有这里会说"不"，**不可跳过**：它是防"纯水"的最后一道闸门。但它是体检，不是判官。

## 姿态

对抗性但克制。主动找会让故事立不住的地方，而不是帮用户论证 idea 多好；同时记住，简单本身从来不是毛病。把疑点问尖时，可对照 `references/reject-lessons.md` 里跨语料反复出现的证据缺口，挑最相近的一条用它的自检问句往下追；那是参照，不是打钩清单。

## 几个朴素的问题

不拿禁令表逐条打钩，就问这几句：

- 一个外行审稿人扫一眼，懂不懂这个故事在说什么、为什么值得做？讲不清就先回去把话讲清，不是急着否。
- 外行看懂之后是什么反应？"这个切入点我没想到过"能立住，"这我上我也行"就是 borderline 到 reject 之间。判的是看见这个缺口可不可预料，不是执行难不难：简单照样合法，但要的是事后看简单（看懂了拍大腿），不是谁坐下来第一步都会做的显然；看标题就能猜到结论，独特性通常还没长出来。
- 指标或方法像不像从故事里自然长出来的？读者该先看懂你在乎的那个对象，再明白这个指标 / 这个方法只是把它落实下来的一步。一上来就是性质清单、权重理由、消融，或者一堆模块和损失项，通常说明故事还停在设计备忘录，回去先把对象讲清楚。复杂度要是在悄悄爬（堆参数、要一堆消融、把一个体面概念整套理论实现一遍），多半那个简单的 idea 还没找到。
- 水面下有没有一个小而真的观察撑着？还是只是"换了个说法"？观察还没着落时，最硬的来源是去复现已有工作、亲眼看它的真实水平差在哪：gap 存不存在本身是故事的承重件，这一步是在拿证据，不是提前做工程卫生。
- 这个维度的粒度，审稿人有没有分辨率？太细太内部没人关心，太粗成了空话。
- 故事容不容得下一个把新轴隔离出来的消融？新轴要证明自己真实存在，也承认自己不解释什么，别吞掉旧轴。这类实验研究推进中会自然显现，idea 阶段不必做，留给审稿人当讨论点也不亏。
- 故事主张一个机制时，哪个量在承重？说得出一个最小实验、一个带方向的指标、一个承重变量，还要能设想一次只动这个变量、其余尽量不动的干预，预测下游指标退回基线；预测若只是复述干预本身按定义会发生的事，检验的是定义，不是机制。承重变量说不出来，机制 claim 就还停在相关性。不主张机制的故事（benchmark、数据、诊断）不必硬套这一问。

**干净地补一个圈子在乎的缺失维度，是合格的故事，不因为简单、或"别人没测过"，就判它增量。** 真的空了才说不，简单不是说不的理由。

命中真问题就直说，给最小修法，或打回 divergent 换角度。**不在这里查工程严谨**（复现、污染、baseline、评测脚本可靠性、venue 匹配、可行性），那些等故事锁定后另说。

## 起名字：交给旁观者抽，别自己憋

故事立住后要给它一个名字（标题 / framing / 方法名 / 指标名）。别在原地自己憋——写素材时你带着生成时的纠结，反而看不清哪几个词最该上台，这是当局者迷。把铺好的素材（例子、一句话 story、失败现象，有 abstract 草稿更好）打包给一个干净上下文的 subagent，让它当旁观者：只读素材，圈出已经在承重的那几个名词和动作，用这些词重组两三个候选，不发明新概念。让它只回承重词和候选名，别把推理全拉回来。拿回来只留外行一眼就能想起那个例子的那个，要额外解释才懂的弃掉。好名字往往还带一点引人探究的惊喜感：看到"评测交互算法题"没什么，看到"在未揭示信息下"就想点进去。它常常是从摘要里自然截取、或对话中偶然冒出来的适合包装的亮点，碰到了就用，不强求。

## 结论

三档 + 最优先 2-3 个行动：故事立得住 → 去写（/paper-init 或 /paper-draft + writing-style）；要调 → 回 divergent 或 seed-brief；真不成立 → 换方向。Novelty 没实际检索过 → 标 `unverified; literature check required`，不凭记忆下结论。真去查时先自问"别的社区会把这个机制叫什么"，拿别名再查一轮：同一机制在别的圈子常换个名字，这个盲区是词汇性的，只靠自己的词汇加长时间窗补不回来。对到 closest prior 时把已发表当地板：已发表约等于过时，做到同等水平只能降档投，故事的位置要在地板之上。最终决策权在用户。
